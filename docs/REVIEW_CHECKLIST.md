# 학습 노트 리뷰 체크리스트

정리한 문서를 다시 볼 때 사용하는 체크리스트입니다.

## 구조

- [ ] 제목 계층이 `#`, `##`, `###` 순서로 자연스럽다.
- [ ] 문서 앞부분에서 이 주제가 무엇인지 바로 알 수 있다.
- [ ] 긴 문서에는 Quick Navigation 또는 핵심 목차가 있다.
- [ ] 관련 폴더나 문서로 이동할 수 있는 링크가 있다.

## 내용

- [ ] 개념 설명이 내 말로 정리되어 있다.
- [ ] 예시 코드가 너무 길지 않고 핵심을 보여준다.
- [ ] 실수하기 쉬운 포인트나 오류 사례가 남아 있다.
- [ ] 외워야 할 내용과 이해해야 할 내용이 구분되어 있다.

## 코드

- [ ] 코드 블록에 언어가 지정되어 있다.
- [ ] 실행 결과가 중요한 예시는 출력 예시가 함께 있다.
- [ ] 보안상 공개하면 안 되는 값은 포함되어 있지 않다.
- [ ] 실습용 로컬 경로나 임시 파일명이 그대로 남아 있지 않다.

## 마무리

- [ ] 마지막에 한 줄 요약 또는 정리 기준이 있다.
- [ ] 나중에 다시 봐도 바로 적용할 수 있는 형태다.
- [ ] README 목차나 루트 링크가 필요한 경우 갱신했다.

## 프로젝트 회고

프로젝트 회고 문서(`projects/`)를 공개하기 전에 확인합니다.

- [ ] 서비스가 풀려는 문제와 사용자가 첫 화면에서 보는 것이 서두에 있다.
- [ ] 수치마다 측정 조건(환경, 기간, 표본)이 함께 적혀 있다.
- [ ] 시연·화면 캡처가 실제로 어떤 환경에서 만든 것인지 사실대로 적혀 있다.
- [ ] 대표 문제가 문제 → 판단 → 결과 순서로 정리되어 있다.
- [ ] 소스를 공개할 수 없는 경우, 설계 판단과 검증 기록으로 내용을 뒷받침한다.
- [ ] IP, 포트, 도메인, 키, 계정, 팀원 실명 같은 공개하면 안 되는 값이 없다.
- [ ] `projects/README.md`의 요약표와 루트 README의 프로젝트 표를 갱신했다.
