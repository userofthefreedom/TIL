# 채용 공고 수집 + 자소서 초안 작성 도구 (job_find)

## 한 줄 소개

사람인·원티드·자소설닷컴에서 채용 공고를 모아 조건에 맞는 것만 걸러내고, 직무·도메인 관련성 순으로 정렬한 뒤, 고른 공고는 AI가 자소서 초안까지 써 주는 개인용 CLI 도구입니다. 직접 취업 준비에 쓰면서 계속 개선하고 있습니다.

## 문제 정의

채용 정보를 여러 플랫폼에서 반복해서 확인하는 일은 시간이 많이 들고, 관심 조건과 맞지 않는 공고를 걸러내는 일도 번거롭습니다. 공고를 고른 뒤에도 회사·직무마다 내 경험 중 어떤 것을 근거로 쓸지 정리해 자소서를 쓰는 데 또 시간이 듭니다.

처음에는 "여러 사이트 공고를 모아 조건대로 거르는 수집기"로 시작했고(v1~v2), 실제로 써 보면서 **수집 → 랭킹 → 검수 → 선택 → 자소서 초안**까지 이어지는 도구로 다시 설계했습니다(v3, Phase 8~).

## 주요 기능

```text
① collect  - 사람인·원티드·자소설닷컴에서 오늘 공고를 가져와 조건에 맞는 것만 저장
② evaluate - 직무·도메인 관련성 순으로 정렬해 상위 N건만 남김 (로컬 모델, 무료)
③ verify   - (선택) 목록 요약과 실제 상세 요건을 AI로 대조해 오탐 확인
④ add      - (선택) 시스템이 못 찾은 공고를 URL로 직접 추가
⑤ select   - 자소서를 쓸 공고를 최대 4개 선택
⑥ write    - 공고마다 AI가 자소서 초안 작성
추가: profile-init / profile-audit - 자소서 재료 지식베이스 생성·점검
```

- **필터**: 제목·직무 태그 키워드, 지역, 신입/경력 다중 선택, 연차 범위, 제외 단어, 회사 블랙리스트, D-day 표시
- **텍스트 파일 기반 조작**: `output/jobs_all.txt`에서 `[ ]`를 `[X]`(제외), `[자소서]`(작성 대상), `[상태]`(지원 상태 기록)로 바꾸는 마커 방식
- **자소서 파이프라인**: 계획 → 계획 평가 → (필요 시 재계획) → 작성 → 초안 평가 → (필요 시 재작성) 루프. 역할 5개(planner, plan evaluator, writer, draft evaluator, verifier)마다 provider를 따로 지정 가능
- **프로필 지식베이스**: 정체성, 경력 요약, 프로젝트·역량 카드, 실패/갈등 사례 등을 조각으로 나눠 두면, 공고 요구사항에 맞는 경험만 골라 문항별 근거로 배치
- **기업 정보**: DART 오픈API로 회사 정보를 조회하고, `claude_cli` 사용 시 계획 단계에서 웹 검색
- **안정성**: 소스 일부 실패·페이지 상한 감지와 `run_log.txt`, 사람과 비슷한 요청 패턴으로 IP 차단 방지

## 기술 스택과 사용 이유

| 기술 | 사용한 이유 |

## 어려웠던 점과 해결

- **키워드 필터의 한계**: "기획, PM"처럼 적으면 문자 그대로 겹치지 않는 비슷한 공고를 놓쳤습니다. → threshold 이진 필터를 버리고, 로컬 한국어 임베딩으로 직무·도메인 둘 다 가까운 공고를 위로 올리는 랭킹으로 바꿨습니다.
- **목록 요약과 실제 요건의 불일치**: 목록에서는 맞아 보여도 상세 요건이 다른 공고가 있었습니다. → `verify` 단계로 상세 요건을 AI로 대조하고, 사람인처럼 요건이 이미지인 경우 비전으로 읽게 했습니다. 다만 LLM 판정이 재검수 때 달라지는 사례가 있어 결과를 "참고용"으로 명시했습니다.
- **없는 정보를 지어내는 초안**: 공고 원문이나 문항을 모르면 AI가 내용을 꾸며낼 수 있었습니다. → 확인하지 못한 부분은 초안 앞에 가정이라고 밝히게 하고, `materials/notes.md`에 실제 문항을 넣으면 그것을 최우선으로 따르게 했습니다.
- **"무료"라고 생각한 CLI provider의 비용**: Claude Code CLI 재사용은 API 키가 필요 없지만, 호출마다 기본 컨텍스트 때문에 토큰이 상당히 소모되는 것을 실측으로 확인했습니다. → README에 요금제별 주의점과 웹 검색 사용 시 약 1.5~2배 증가를 그대로 적었습니다.
- **검증되지 않은 기능 유지**: `codex_cli` provider는 끝내 실사용 검증이 안 됐습니다. → 남겨 두기보다 폐기하는 쪽을 택했습니다(Phase 20).

## 배운 점

- 직접 매일 쓰는 도구는 처음 설계보다 실사용 피드백이 구조를 더 크게 바꾼다는 점 (수집기 → 자소서 파이프라인)
- AI가 만든 결과는 "생성 → 평가 → 재작성" 루프와 근거 없는 내용 금지 규칙이 있어야 믿고 쓸 수 있다는 점
- 비용이 드는 단계(검수·작성)와 무료 단계(수집·랭킹)를 분리하면 반복 실행 부담이 줄어든다는 점
- 비공식 API나 스크래핑은 이용약관·차단 위험을 문서에 숨기지 않고 알리고, 끌 수 있게 만들어야 한다는 점
- 플랫폼마다 지역, 직무, 경력 표현 방식이 달라 필터링 규칙을 유연하게 설계해야 한다는 점
