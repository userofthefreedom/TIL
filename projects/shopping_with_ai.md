# AI 쇼핑 어시스턴트

## 한 줄 소개

사용자가 상품 사진을 올리면 AI가 상품을 탐지·분류하고, 유사 상품과 가격을 찾아 추천하며, 대화형 챗봇으로 쇼핑을 돕는 Gradio 기반 웹 서비스입니다. SSAFY AI 과정 과제로 수행한 개인 프로젝트입니다.

## 문제 정의

마음에 드는 옷 사진은 있는데 상품명을 모르면 검색어부터 막힙니다. 과제 요구사항은 "사진 한 장으로 상품 인식 → 정보 설명 → 유사 상품 가격 비교 → 예산 맞춤 추천 → 구매 링크"까지를 하나의 업로드·대화 흐름 안에서 처리하는 것이었습니다. 성능 기준으로는 탐지 mAP@0.5 70% 이상, 업로드 후 3초 이내 결과 제공이 주어졌습니다.

## 주요 기능

- 상품 사진 업로드 → YOLOv8(DeepFashion2 사전학습)으로 탐지와 13개 패션 카테고리 분류
- 옷 색상 인식: 탐지 영역에서 K-means로 대표색 추출 → HSV 규칙으로 한국어 색상명(카키, 남색 등) 변환 → 검색어에 반영
- CLIP 제로샷으로 세부 종류 추정 (예: "긴팔 아우터" → "패딩")
- 로컬 텍스트 벡터 검색(KO-SRoBERTa + ChromaDB) 우선, 부족할 때만 네이버 쇼핑 API 실시간 검색
- CLIP 이미지 유사도로 후보 재정렬
- 자연어 예산 조건 파싱("10만원 이하", "더 저렴한") 후 필터링·가격순 정렬
- "최신/신상/재고" 같은 신선도 키워드 감지 시 네이버 실시간 재검색
- LLM 챗봇이 대화 맥락(어떤 상품 이야기 중인지)을 유지하며 응답
- 추천 상품 카드에서 실제 쇼핑몰 구매 링크로 이동

## 동작 흐름

```text
이미지 업로드
-> YOLOv8 탐지 (bbox + 카테고리)
-> 색상 인식 (K-means + HSV 규칙)
-> "카테고리 + 색상 + 세부 종류" 설명 생성 (CLIP 제로샷)
-> 로컬 텍스트 벡터 검색 (KO-SRoBERTa, ChromaDB)
   -> 부족하면 네이버 쇼핑 API 검색 후 이미지/텍스트 컬렉션에 색인
-> CLIP 이미지 유사도로 재정렬
-> (예산 조건이 있으면) 필터링/정렬
-> LLM 챗봇 응답 + 추천 카드
```

## 기술 스택과 사용 이유

| 기술 | 사용한 이유 |
| --- | --- |
| YOLOv8 (DeepFashion2) | 상품 위치 탐지와 패션 카테고리 분류 |
| CLIP ViT-B/32 | 업로드 이미지와 후보 상품 이미지의 시각적 유사도 비교, 제로샷 세부 종류 분류 |
| KO-SRoBERTa | 한국어 상품 설명 텍스트 임베딩으로 로컬 검색 |
| ChromaDB | 이미지(`product_images`)·텍스트(`product_text`) 임베딩 컬렉션 저장 |
| Llama 3.2 Korean Bllossom 3B + LangChain | 한국어 대화형 챗봇 응답 생성 |
| 네이버 쇼핑 검색 API | 실제 상품·가격·구매 링크 확보 |
| Gradio | 업로드 → 대화 흐름을 빠르게 하나의 화면으로 구성 |
| FastAPI, Docker Compose, Prometheus, Grafana | 앱을 감싸 GPU 패스스루 로컬 배포 스택과 모니터링 구성 |

## 어려웠던 점과 해결

- **3초 응답 목표 미달**: Version 1 검증에서 네이버 상품 이미지를 순차로 다운로드·임베딩하는 구조가 병목이었습니다. → 병렬 다운로드와 이미 색인된 상품의 재다운로드 생략으로 개선했습니다.
- **색상 오분류**: 네이비 크롭 티셔츠가 "파란색", 카키 필드 재킷이 "회색"으로 나왔습니다. → 실제 사진으로 검증하며 HSV 규칙을 단계적으로 보정했습니다.
- **카테고리 그대로 검색 시 스타일 편향**: 원본과 다른 스타일이 추천됐습니다. → 동의어 검색으로 후보군을 넓혔습니다.
- **채팅 타이밍 버그**: 이미지 분석이 끝나기 전에 질문하면 "정보 없음"으로 답했습니다. → 재현으로 원인을 확인하고 분석 중에는 입력을 잠갔습니다.
- **요구사항 누락 발견**: 원본 요구사항을 다시 읽다가 KO-SRoBERTa 텍스트 벡터 검색 레이어가 빠진 것을 발견했습니다. → "로컬 벡터 검색 우선, 부족할 때만 네이버 실시간 검색" 구조로 아키텍처를 바꿨습니다.
- **보안·상태 버그**: 자체 코드·보안 리뷰에서 Stored XSS, 세션 간 챗봇 기록이 섞이는 상태 오염 버그를 발견해 수정했습니다.
- **정리 중 회귀**: 배포 파일을 `deploy/`로 옮기면서 `docker compose build`가 실패하는 경로 문제가 생겼습니다. → 최종 감사에서 이 회귀를 포함해 문제 14건을 찾아 수정하고, 나머지는 이유를 남겨 보류했습니다.

## 배운 점

- "완성"을 선언한 뒤에도 원본 요구사항 문서를 다시 대조하면 빠진 레이어를 찾을 수 있다는 점
- 외부 API를 매번 부르기보다 로컬 색인을 먼저 쓰는 구조가 속도와 요청 수를 함께 줄인다는 점
- 모델 정확도 문제(색상 등)는 지표보다 실제 사진으로 직접 써 보는 검증에서 더 잘 드러난다는 점
- 파일 구조를 정리하는 리팩터링도 빌드를 깨뜨릴 수 있으므로 정리 후 재검증이 필요하다는 점
