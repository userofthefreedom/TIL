# FirstHome Navigator AI

## 한 줄 소개

첫 주택 마련을 준비하는 사용자가 청약 공고, 자금 계획, 금융상품, 지도, 커뮤니티, AI 코치를 한 흐름에서 확인할 수 있도록 만든 청약 큐레이팅 서비스입니다. SSAFY 15기 관통 프로젝트 **우수상** 수상작입니다.

## 문제 정의

청약 정보는 공고문, 자격 조건, 자금 일정, 주변 위치, 금융상품 정보가 흩어져 있어 사용자가 자기 조건에 맞는 선택지를 판단하기 어렵습니다. 사용자가 실제로 궁금한 것은 "공고 목록"이 아니라 **"내 조건에 맞는지", "돈은 얼마나 부족한지", "무엇을 먼저 확인해야 하는지"**였습니다. 이 프로젝트는 사용자의 조건을 기준으로 청약 후보와 자금 준비 방향을 계산하고, 공식 근거와 AI 코치 설명을 함께 제공하는 것을 목표로 했습니다.

## 핵심 설계

### 금융상품 추천: 최고 금리순이 아니라 "내 자금 준비에 맞는 순"

금리만으로 정렬하면 사용자의 준비 기간이나 월 저축 여력과 맞지 않는 상품이 위로 올라옵니다. 그래서 여러 기준을 합산해 0~100점으로 제한한 점수를 사용했습니다.

1. **준비 기간 적합도**: 목표 준비 기간과 상품 기간이 가까울수록 높게 (일치 > 3·6·12·18개월 차이 순)
2. **월 납입 가능성**: 월 저축 가능액과 상품 월 납입 한도의 적합도
3. **금리**: 기본·우대 금리 중 활용 가능한 최고 금리. 단, 금리만으로 결정되지 않도록 다른 조건과 함께 반영
4. **목적성·신뢰도**: 청약·주거·내집 마련·청년·적금 계열 우선, 예금자 보호 여부와 공식 출처 URL을 신뢰도 신호로 반영
5. **옵션 다양성**: 기간별 금리 옵션이 여러 개면 비교 가능성 가점

### 생성형 AI: 판단자가 아니라 설명 보조자

- AI 코치·챗봇·PDF 보조 분석에만 LLM을 쓰고, 추천 점수와 자금 계산은 규칙 기반으로 계산했습니다.
- **안전 필터**: "청약 당첨 보장", "대출 가능 보장" 같은 허위 확정 표현을 제한하고 공식 공고문 확인을 우선 안내합니다.
- **fallback**: API 키 오류나 외부 AI 장애 시에도 규칙 기반/template 답변으로 시연 흐름이 끊기지 않게 했습니다.

### 데이터: 실제 데이터 우선 + fixture 보강 + 공식 근거 표시

공고마다 PDF 형식이 다르고 외부 API 데이터가 누락되는 경우가 많았습니다. mock 데이터로 시작해 실제 API 키 연동으로 바꾼 뒤(5/18~5/19), 부족한 지역은 fixture로 보충하고(6/2 "fixture as backup"), 화면에는 어떤 값이 공식 근거에서 왔는지 표시하는 방식으로 정리했습니다.

## 어려웠던 점과 해결

- **불완전한 실제 데이터**: 공고 PDF 형식이 제각각이고 외부 API 값이 비는 경우가 많았습니다. → 규칙 기반 추출을 먼저 하고 부족할 때만 LLM으로 보조, 부족 지역은 fixture로 보충, 화면에 근거 출처를 표시했습니다.
- **발표 환경 안정성**: 로컬 서버를 외부에 공개해 여러 명이 동시에 접속해야 했습니다. → cloudflared로 시작해 ngrok으로 전환하고, 다중 사용자 테스트와 발표 직전 캐시 워밍업 절차를 README에 남겼습니다.
- **AI 응답의 위험한 표현**: 금융·청약 영역이라 단정적인 답변이 문제가 될 수 있었습니다. → 안전 필터로 보장성 표현을 막고 공식 공고문 확인을 안내했습니다.

## 배운 점

- 실제 데이터는 완전하지 않기 때문에 rule-first, fixture 보강, 공식 근거 표시가 함께 필요하다는 점
- 추천 서비스는 점수 계산보다 "왜 추천됐는지"를 설명하는 구조가 중요하다는 점
- AI 기능은 실패 가능성을 전제로 fallback과 안전한 표현 제한을 설계해야 한다는 점
- 프로젝트 마감에는 기능 구현만큼 문서, 시연 안정성, 다크/라이트 모드 같은 화면 가시성, 동시 접속 테스트가 중요하다는 점
